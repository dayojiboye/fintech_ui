# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

- `npm start` — start the Expo dev server (`npm run ios` / `npm run android` / `npm run web` target a platform)
- `npm run lint` — ESLint via `expo lint` (flat config extending `eslint-config-expo`)
- `npx tsc --noEmit` — type-check (strict mode; there is no script for it)

There is no test runner configured. `/ios` and `/android` are gitignored: native projects are generated by Expo prebuild, so native config changes belong in `app.json`.

Do not run `npm run reset-project`. It is the Expo template script and moves `app/`, `components/`, `hooks/`, `constants/` and `scripts/` into `app-example/`.

## Architecture

A UI-only fintech app (Expo SDK 57, React Native 0.86, new architecture, React Compiler and typed routes enabled). All data is hard-coded in the components; there is no API, state library or persistence.

**Routing vs. screens.** `app/` holds Expo Router route files only. Each route is a thin wrapper that renders a screen from `screens/<name>/index.tsx`, and that screen's sections live in `screens/<name>/components/`. Only Home is built out so far; the other tabs (`cards`, `transfer`, `services`, `profile`) are placeholders. Shared components go in `components/`, generic primitives in `components/ui/`.

**Navigation.** `app/_layout.tsx` wraps a root `Stack` in `GestureHandlerRootView` and `HeroUINativeProvider`, and imports `global.css`. `app/(tabs)/_layout.tsx` uses `Tabs` from `expo-router/js-tabs` (the JS bottom-tabs, not native tabs) with a custom `tabBar` from `components/tab-bar.tsx`. That tab bar reimplements tab press/long-press emission, height reporting via `BottomTabBarHeightCallbackContext`, and an animated indicator. It is absolutely positioned on iOS, so scrollable screens need bottom padding (Home uses `pb-[100px]`). React Navigation APIs such as `CommonActions` are imported from `expo-router/react-navigation`.

**Styling: Uniwind + HeroUI Native.** Styling is Tailwind v4 classes via `className`, compiled for React Native by Uniwind (wired up in `metro.config.js`). Uniwind also provides `contentContainerClassName` and safe-area utilities such as `pt-safe`.
- Theme tokens are CSS variables in `global.css`, with light/dark variants for the HeroUI Native theme. The brand color `--app-blue` is exposed as `--color-app-blue` via `@theme inline`, which gives the `text-app-blue` / `bg-app-blue` classes.
- When a raw color value is needed in JS (icon colors, inline styles), read it with `useCSSVariable("--color-app-blue")` from `uniwind` rather than hard-coding it.
- Use `cn` from `heroui-native` for conditional class names.
- `uniwind-types.d.ts` is generated by the Metro plugin; don't edit it by hand.
- Icons come from `react-native-remix-icon` (`<RemixIcon name="..." />`).

**Expo template leftovers.** `parallax-scroll-view`, `hello-wave`, `external-link`, `themed-text`, `themed-view`, `ui/collapsible`, `ui/icon-symbol*`, `constants/theme.ts`, `hooks/use-theme-color.ts` and `hooks/use-color-scheme*.ts` came from the Expo template. No route or screen imports them. New UI should use Uniwind classes and HeroUI components, not the `Colors` / `useThemeColor` theming.

## Conventions

- Prettier (`.prettierrc.js`): no semicolons, double quotes, 2-space indent, 120-column width. Template leftovers still use semicolons; app code does not.
- Import paths use the `@/*` alias for the project root. Images are loaded with relative `require()` from `assets/images/`.
- `screens/` and section components use default exports. Shared components in `components/` are mostly named exports (`section-header` is the exception).
